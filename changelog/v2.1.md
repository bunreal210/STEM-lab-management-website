## Tổng quan

Sửa lỗi nghiêm trọng khiến người dùng không thể tạo tài khoản: sau khi đăng ký thành công ở phía client, thông tin người dùng không được ghi vào bảng `user_profiles` trong Supabase.

---

## 🐛 Lỗi đã sửa

### Không thể tạo tài khoản — thông tin không lưu vào Supabase

**Nguyên nhân gốc rễ (Root Cause):**

Khi `supabase.auth.signUp()` được gọi và Supabase đang bật chế độ **"Email Confirmation"**, hệ thống trả về `data.user` nhưng chưa có session (chưa đăng nhập). Code cũ sau đó cố gắng `INSERT` thủ công vào bảng `user_profiles`, nhưng lệnh này bị **Row Level Security (RLS) chặn** vì:
- `auth.uid()` trả về `null` (không có session)
- Policy `"Users insert own profile"` yêu cầu `auth.uid() = id` nên từ chối request

**Kết quả:** Tài khoản được tạo trong `auth.users` nhưng bảng `user_profiles` hoàn toàn trống — người dùng không thể đăng nhập hoặc sử dụng các tính năng.

## ✅ Giải pháp

### 1. Database Trigger tự động tạo Profile (`supabase-trigger-fix.sql`)

Tạo PostgreSQL trigger `on_auth_user_created` chạy phía server (với `SECURITY DEFINER`) mỗi khi có user mới trong `auth.users`. Trigger này không bị RLS chặn và tự động tạo bản ghi trong `user_profiles`.

```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  INSERT INTO public.user_profiles (id, name, class_name, dob, role, phone)
  VALUES (
    NEW.id,
    COALESCE(NEW.raw_user_meta_data->>'name', split_part(NEW.email, '@', 1)),
    COALESCE(NEW.raw_user_meta_data->>'class_name', ''),
    NULLIF(NEW.raw_user_meta_data->>'dob', '')::date,
    'student',
    COALESCE(NEW.raw_user_meta_data->>'phone', '')
  )
  ON CONFLICT (id) DO NOTHING;
  RETURN NEW;
END;
$$;
```

### 2. Cập nhật hàm `handleRegisterSubmit` (`app/page.tsx`)

Truyền toàn bộ thông tin người dùng (`name`, `class_name`, `dob`, `phone`) vào `options.data` của `supabase.auth.signUp()` — Supabase lưu vào cột `raw_user_meta_data` của `auth.users`. Trigger SQL sẽ đọc từ đây để tạo profile.

```typescript
// TRƯỚC (lỗi)
const { data, error } = await supabase.auth.signUp({ email, password })
if (data.user) {
  await supabase.from('user_profiles').insert({ ... }) // ← bị RLS chặn
}

// SAU (đúng)
const { data, error } = await supabase.auth.signUp({
  email,
  password,
  options: {
    data: { name, class_name: className, dob, phone }, // ← trigger đọc từ đây
  },
})
// Không cần INSERT thủ công nữa — trigger tự xử lý
```

### 3. Cải thiện UX sau đăng ký

Phân biệt 2 trường hợp:
- **Email confirmation TẮT** (`data.session` tồn tại): Thông báo đăng nhập thành công ngay
- **Email confirmation BẬT** (`data.session` là null): Hướng dẫn người dùng kiểm tra email

## 📋 Hướng dẫn áp dụng

Để fix hoạt động, **bắt buộc** phải chạy file SQL trigger trong Supabase:

1. Mở **Supabase Dashboard → SQL Editor**
2. Tạo query mới và paste nội dung file `supabase-trigger-fix.sql`
3. Nhấn **Run**

Tuỳ chọn (khuyến nghị khi test): Tắt **Email Confirmation** trong  
`Authentication → Settings → Email → Enable email confirmations`
